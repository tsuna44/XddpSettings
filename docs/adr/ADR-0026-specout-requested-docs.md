# ADR-0026: 人の依頼でファイル・モジュールを調べて SPO の資料にできるようにする理由

Status: Accepted（承認済み）
Date: 2026-10-14

- プラン: [plans/PLAN-20261013-specout-requested-docs.md](../../plans/PLAN-20261013-specout-requested-docs.md)（P4b）
- 前提 ADR: [ADR-0023](ADR-0023-specout-two-layer-output.md)（出力の2層化・追加下調べ。§3 の「人は選ばない」を本 ADR で改訂する）、
  [ADR-0025](ADR-0025-specout-ripple-runs.md)（波紋調査の記録・採用した調査の合算・`xddp-investigate`・"## Specout Finish"）
- 調査記録: [docs/specout-redesign-study-2026-10.md](../specout-redesign-study-2026-10.md)（§6 の P4b・§7.1 の G5）

## Context

- SPO のモジュール資料（LLM が母体コードを読んで書く構造・シーケンス・データフロー・処理の観察）を書く機会は、下調べと追加下調べだけだった。
  追加下調べの対象は「シードが直接参照するのに台帳に無いファイル」に機械的に決まる（ADR-0023 §3）。
- ADR-0023 は「人は母体コードを知らないことがあり、資料にするものを選べない」を理由に、人が資料にするものを選ぶ経路（調査資料 D6）を取り消した。
- しかし人は、LLM が書いた SPO と波紋調査の結果から母体コードを把握できる。「選べないことがある」は人に選ぶことを**求めない**理由にはなるが、
  **選べなくする**理由にはならない。資料の無いモジュールは SPO §2〜§4 の材料にならず、工程11 の最新仕様書にも入らないため、
  人が母体を理解したい箇所に資料を足す手段が必要だった。

## Decision

### 1. 人は選ばなくてよいが、依頼できる（ADR-0023 §3 の改訂）

- 自動の追加下調べは今のまま動く（人に選ぶことは求めない）。加えて `/xddp-investigate {CR} document 対象…` で人が資料を依頼できる。
- 依頼の単位はファイル・ディレクトリ・モジュール名（SPO §5.0・§8 の名前）（J1）。任意で観点（`--focus`）を受け取り、エージェントに渡す（J5）。
- `suggest` は資料の無いモジュールの候補をスクリプトが示す（シードの直接参照で資料の無いファイルを持つものが先、名前の一致のみが全部のものは最後）。
  LLM は根拠を添えてよいが、依頼するかは人が決める。
- 資料を書くのは下調べのエージェント（`PRELIM_MODE: requested`）。台帳の工程は `依頼調査` で、追加下調べの累計の上限に数えない（J4）。

### 2. 依頼は LLM の判断で拒否しない（J3・J9）

- 人が依頼したファイルは、CRS の変更対象の振る舞いとの関係を確かめられなくても資料にする。台帳の「関係する振る舞い（CRS）」に `確認できず` と書き、
  SPO §8 にスクリプトが注記を書く（モジュール資料には注記を書かない。統合→分割の移し替えで書式が崩れず、工程11 の最新仕様書に CR 固有の注記が写らないように）。
- `確認できず` の行は影響の一覧（§1 の検出モジュール数・採用した調査が0件の §5.0・§5.1）から外す。採用した調査がある経路の §5.0〜§5.2 は
  波紋調査の要約から作るため変えない（波紋調査が届いたモジュールは、CRS との関係によらず波紋調査の根拠で影響する機能である）。
- 拒否はしないが、実行の前にスクリプトの懸念（名前の一致だけの到達・追加下調べが関係なしと判断したファイル）と SPO から根拠を挙げられる懸念を示して
  1回だけ「続けますか／対象を変えますか」と尋ね、実行の後はエージェントがファイルごとに `確認できず` の理由と助言を返す。根拠を挙げられない推測は伝えない。

### 3. 大きさは止めずに確かめる（J2）

- 展開後のファイル数が `SPECOUT_MAX_AFFECTED_FILES` を超えたら人に「全部／絞る」を尋ねる（累計の上限にはしない）。
  エージェントはモジュール単位で1回 `SPECOUT_MAX_AFFECTED_FILES` ファイルまでに分けて順に起動する（統合パスでは同じ SPO の下書きに書くため並列にしない）。

### 4. 資料のあるファイルへの追記は人が決め、スクリプトが検査する（J7）

- 資料のあるファイルへの依頼は「すでに資料として記述しています。追記が必要ですか？」と尋ね、「必要」と答えたファイルだけを追記する（要否を LLM に判断させない）。
- 追記は既存の記述を変えずに決まった節（分割パスは §2 の末尾の `### 2.7 追加調査（依頼調査）`、統合パスは `### 2.X.10`）に足すだけとし、
  `specout_bfs.py doc-append-check` が写しと比べて検査する（既存の全行が同じ順で残る・加わった行が追記の節か変更履歴の表の中だけ・観察メモは行の追加だけ・台帳は不変）。
  満たさなければ、またはエージェントが `OK` を返さなければ、書き先・観察メモ・台帳を写しに戻す（全部入るか何も入らないか）。
- 追記は台帳を変えないため、依頼調査の記録 `work/doc-request-log.md`（スクリプトだけが書く）で SPO の仕上げの要否（`finish-needed` の `docs-changed`）と
  document agent の入力の指紋を判定する。

### 5. 人が名指しした対象には、量を抑える既定の除外を効かせない（J8）

- 除外パターン（`SPECOUT_EXCLUDE_PATTERNS`。テストコード等）は調査と結果の量を抑えるための既定であり、人が知りたいと考えた観点を優先する。
  名指しした対象そのものが除外パターンに一致するなら、その対象と配下には一致したパターンだけを適用しない。配下の他のパターンと、
  名指しした対象より下の階層で初めて一致するファイルには今までどおり適用する（ディレクトリの名指しは「この範囲」の意味）。
  ディレクトリ・モジュールの照合は `/` で終わるパターンだけで行う。
- 名指しで調べた除外パターンのファイルは、SPO を組み立てるたびに台帳の工程 `依頼調査` の行と除外パターンの照合で見分け（記録に依らない）、
  §5.5 と影響の一覧から外して §8 に注記する。document agent にも `PATTERN_OVERRIDE_FILES` で渡し、本番のコードと区別させる。
  「資料あり」の判定（§5.0 の「資料」列・§5.2・§8）は変えない（§5.2 の作り方は本 ADR の対象外）。

### 6. 統合パスの下書きの消失・上書きを黙って起こさない

- 依頼調査では、工程4a が未完了のときや SPO の仕上げを見送ったときに、統合パスの下書き `work/module-drafts/` が次の SPO の仕上げまで残る。
  その間の統合→分割の移し替えで下書きが捨てられる、人が直した §2.A… が古い下書きで置き換えられる、の2つを防ぐため:
  - 抜き出しは今回の対象のファイルを持つモジュールだけにし、抜き出し元の節の SHA-256 をスクリプトだけが書く記録 `.source-sha256.json` に残す。
  - 差し込み・移し替えの前に記録と今の節を比べ、違えば何も書かずに止まる（人が見比べて揃える）。移し替えは下書きから資料を作り、
    §2.A… に節の無い新しいモジュールの下書きは台帳に行があるときだけ資料にする。

## Consequences

- 依頼したときだけ、モジュール資料・台帳・観察メモ・SPO の LLM が書く欄が変わる。依頼調査が無ければ工程4a の出力は変わらない。
- document agent の入力の指紋の項目が1つ増えたため、実装後の最初の SPO の仕上げでは依頼調査の無い repo でも document agent が1回動く。
- 波紋調査が届いたモジュールに資料を足すと SPO §5.2 と回帰テストの対象が変わる（資料の有無で回帰テストの範囲が変わるのは今の設計の問題であり、
  [PLAN-20261013-regression-scope-from-chd](../../plans/PLAN-20261013-regression-scope-from-chd.md) で見直す）。
- 新規のファイルを資料のあるモジュールに書き足すときは、追加下調べと同じく文章・図の節を更新するため、人が直した文章が書き換わりうる（検査しない）。
  人の記述を守りたいファイルは、資料のあるファイルとして追記で頼む。
- 追記の検査は加わった行の位置を `difflib.SequenceMatcher` で求めるため、まれに正しい追記を戻すことがある。誤るのは戻す側だけで、既存の記述は失われない。

## 対象外（後続）

- 方式検討エージェント等の LLM からの依頼、依頼調査の後の SPO の AI レビュー、資料の削除、回帰テストの範囲の決め方。
- スモークハーネスへの `xddp-investigate` の追加（P4a と同じく手動確認で代える）。
