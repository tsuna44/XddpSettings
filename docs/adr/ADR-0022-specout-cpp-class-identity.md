# ADR-0022: 工程4a 波紋調査で、C/C++ のマクロを構文解析の前に無害化し、C++ のメソッド・メンバー変数をクラス単位で追う理由

Status: Accepted（承認済み）
Date: 2026-10-12

- プラン: [plans/PLAN-20261011-specout-cpp-identity.md](../../plans/PLAN-20261011-specout-cpp-identity.md)（P2b）
- 前提 ADR: [ADR-0019](ADR-0019-specout-static-slicer.md)（波紋調査の判定の置き換え）、[ADR-0021](ADR-0021-specout-symbol-identity.md)（リンケージによる名前の区別・`name-only`）
- 調査記録: [docs/specout-redesign-study-2026-10.md](../specout-redesign-study-2026-10.md)（§4.3・§5.4・§6 の P2b）、付録 [docs/specout-redesign-study-2026-10-cpp-sample.md](../specout-redesign-study-2026-10-cpp-sample.md)

## Context

ADR-0021（P2）は C の static・ローカル変数による「名前が同じだけの別物」への到達を扱った。C++ の母体（spdlog・fmt）では、P2 の後も到達はほぼ変わらなかった
（spdlog PR #3671 の確定 88 → 88。うち name-only 74）。付録のサンプル 29 件のうち 24 件が名前の一致のみで、原因は次の2つだった。

- **構文解析の誤り（23 件）:** 宣言を飾るマクロ（`SPDLOG_INLINE`・`FMT_API`）・名前空間を開くマクロ（`SPDLOG_NAMESPACE_BEGIN`）が識別子のまま tree-sitter に渡り、
  エラー回復で名前空間の塊を関数定義と誤る。偽の関数 `namespace` が「含む関数」・次の波のシンボルになり、204 回送られた。
  ループマクロの書き換えが改行をまたいでコンストラクタを書き換え（偽の関数 `__xddp_iter`）、行番号もずらしていた。
- **同名のメソッドを区別しない（1 件。第1波以降で効く）:** `sink_it_` は 25 クラス、`flush_` は 24 クラスにある。修飾なしの名前で送るため、兄弟クラスの override や
  別クラスの同名メソッド（`size`・`flush`・`close`）に届く。呼び出し先の要約も素名を鍵にしていて、クラスをまたいで混ざっていた。

C++ のメソッド名へのヒット 3,050 件の形を数えると、メソッドの本体の中の修飾なしの呼び出し 23%・宣言と定義 21%・修飾 `X::foo` 14%・`obj.foo` 16%・`this->foo` 0% で、
受け手のクラスを修飾・含むメソッドのクラス・宣言の型から決められるものが大半だった（プラン §1.1）。

## Decision

### 1. マクロは構文解析の前に、同じ行の中で無害化する（段階 A）

`specout_macros.py`（標準ライブラリのみ）がリポジトリの全 C/C++ ファイル（除外したファイルを含む）の `#define` を正規表現で事前走査し、オブジェクト形式のマクロのうち、
**すべての定義が同じ1つの種類に当たるもの**だけを置き換える。

- **名前空間マクロ:** 本体が `namespace X {` の並び（開く側）か `}` の並び（閉じる側）だけで、すべての定義が同じ側・同じ段数。本体に置き換える。
- **宣言を飾るマクロ:** 本体が空か、決まった語（`inline`・`static`・`__attribute__((…))`・`[[…]]` 等）の並びだけ。意味を持つ語だけを残す
  （`virtual` は定義の1つでも含めば残し、`static`・`extern`・`thread_local` はすべての定義が含むときだけ残す。どちらも見落としにならない向き）。
- **空にした組:** 空の定義を持つ「構造を開く側」（`export {`・`try`・名前空間を開く）と「閉じる側」（`}`・`catch (…) {…}`）のマクロで、両方の空の定義が同じ場所
  （同じファイルの同じ条件コンパイルの枝）にあり、空でない定義どうしも同じ場所にある組だけを、両方とも空にする（fmt `FMT_BEGIN_EXPORT`/`FMT_END_EXPORT`、spdlog `SPDLOG_TRY`/`SPDLOG_CATCH_STD`）。

置き換えは同じ行の中だけで行い、改行を変えない（行番号を保つ）。プリプロセッサ指令の行・コメント・文字列の中は置き換えない（インクルードガード・機能フラグの
`#ifdef` を壊さないため）。定義ごとに種類や括弧の段数が違うマクロは置き換えない（開く括弧と閉じる括弧の数が合わなくなり、誤りがかえって増えるため）。
置き換えたマクロ自体へのヒットは `file-scope`（注記 `neutralized-macro`）とし、ファイルを確定するだけで次の波へは送らない（リンケージ・可視性の変更で、
呼び出し元の動作を変えるものではなく、送るとほぼリポジトリ全体が一度に送られるため）。

あわせて、ループマクロの書き換えは引数が1行に収まるものに限り、言語の予約語が「含む関数」・次の波のシンボルになった箇所は送らずに grep 未対応パターン
`parse-artifact` として返す（防御）。クラスの外の定義のクラス名は構文木から取る（テキストの分割ではマクロ・テンプレート引数が混ざる）。

### 2. C++ のメソッド・メンバー変数は `name[CLASS:X]` で送り、ヒットの受け手のクラスで絞る（段階 B）

- **クラスの索引:** C++ として解析するファイルのクラス・構造体ごとに、基底クラス・メソッド（`virtual` は真・偽・不明の3値）・メンバー変数とその型・型の別名を記録する。
  クラス名は素の名前で、名前空間は区別しない（名前空間をまたいで同じ名前のクラスは ADR-0028 で区別する）。名前空間で修飾され、リポジトリのどこにも定義の無い基底クラス（`std::exception` 等）は「外部のクラス」として継承の連鎖の終わりとみなす。
- **送る形:** C++ のメソッド `X::foo` の呼び出し元は `foo[CLASS:X]`、メンバー変数への書き込みは `m[CLASS:B]`（B は `m` を宣言したクラス）で送る。
  **メンバー変数は、ヒットした関数の中の直接の書き込みからだけ送る。** 呼び出し先の要約に入った `[CLASS:…]` は呼び出し元の出口に加えない
  （呼び出し先の中のメンバーの変化は `out(this)`・受け手への書き込みで呼び出し元へ伝わる。`this` を省いたメソッドの呼び出し `flush_();` も、呼び出し元の `out(this)` にする）。
- **受け手のクラス C の決め方:** 修飾 `Y::foo` → Y、メソッドの本体の中の修飾なしの `foo` と `this->foo` → 含むクラス（またはその基底）で `foo` を宣言したクラス、
  `obj.foo` → `obj` の宣言の型（型の別名を解決）、クラス本体の宣言・初期化子並び → そのクラス。決められなければ「決められない」。
- **判定:** C = X、または C が X の派生クラスで間に宣言し直したクラスが無ければ関係あり（`resolved`）。X が C の派生クラスで C の `foo` が virtual なら、動的ディスパッチとして関係あり。
  継承の連鎖がすべて索引にあり、関係が無いと決まったとき（兄弟・無関係のクラス）だけ偽陽性（`other-class`）。決められない・索引に無い基底クラスがある・virtual が不明なら `name-only`。
- **雑音を減らす2つの規則（偽陽性 `other-class`）:**
  - メソッドのエントリ（種類 `function`）で、出現が変数・引数の名前（引数・変数の宣言子、同じ名前のローカル変数のある関数の中の素の出現、呼ばずに参照する `obj.m`）。メソッドの名前はこれらの形で現れない。
  - 「関係あり（`name-only`）」になった `obj.foo` の `obj` の型が、型の別名のすべての定義をたどっても、リポジトリに定義が無いか、基底の句を持たない定義だけの型
    （`std::string`・`std::vector`・`std::function` 等）で、X とその継承の連鎖・テンプレート引数のどれでもない。X の派生クラスになりえない。
- **検索:** `[CLASS:…]` のエントリは C++ として解析するファイルだけを素の名前で検索し、同じ素の名前のエントリの検索は1回にまとめてヒット行をエントリごとに複製する
  （`sink_it_` のような名前で検索の回数がクラスの数だけ増えないようにする。件数一致検証はエントリのコマンドごとにそのまま合う）。
- **要約の鍵:** 要約と種類の表は `summary_key`（`[CLASS:…]` はエントリ文字列、それ以外は今どおり素名）を鍵にする。クラスを指定した要約は、X から `foo` を宣言した最も近いクラス D の定義と、
  virtual なら X の派生クラスの override で作り、決められないときだけ全定義に戻して印（`cls_fallback`）を付ける（黙って戻さない）。
- **シード:** discovery-setup が出す C++ のメソッドのシードは今どおり修飾なしの名前で、第0波は全クラスの同名にヒットする。人が候補表・`--re-discover` で `write[CLASS:file_helper]` のように指定すれば第0波から絞れる。

### 3. メンバー変数を送らない案・呼び出し先の要約からも送る案を採らない

- **プランの当初案（呼び出し先の要約の `[CLASS:…]` も呼び出し元の出口に加える）:** spdlog で送った回数が約30倍（1,422 → 42,336）になり、増えたファイルは判定で全件が本当の依存ではなかった。
- **メンバー変数を送らない案:** 計測した2つの PR では雑音だけを減らしたが、「設定するメソッド」と「使うメソッド」が別の関数にある状態の依存を構造的に取りこぼし、取りこぼしが結果に残らない。
  実開発ではサブ機能の粒度で影響を特定するため、見えない取りこぼしより、`name-only` の印が付いて見える雑音を選んだ（2026-10-12 ユーザー判断）。

## Consequences

計測（本番スクリプトだけで実行。LLM 分類 0 件。詳細は調査資料 §5.4）:

| 母体 | P2 の後 | 段階 A の後 | 段階 B・2つの規則の後 |
|---|---|---|---|
| spdlog PR #3671（確定・うち name-only・送った回数） | 88・74・2,264 | 79・30・1,422 | 72・60・3,193 |
| spdlog PR #3276 | 82・—・2,034 | 52・43・224 | 77・63・3,670 |
| frr M2（C） | 434 | 444 | 444（段階 A と同じファイル） |

- 正解ファイルはすべての実行で第0波。段階 B は送った回数を増やす（クラスごとの検索・判定とメンバー変数の追跡）。
  段階 A の後より確定が増えたファイル（#3276 で 52 → 77）は、修飾なしのシードで第0波から全クラスの同名に届くことと、メンバー変数の追跡による。いずれも `name-only` の印が付く。
- 構文解析の誤り（ERROR 節にかかる行）は spdlog 0.6%・fmt 28.1% まで下がったが、fmt `format.h` のファイル全体の誤りは残る（原因はマクロ以外。特定していない）。
- **限界（名前をたどる方式で捉えられない・区別できないもの）:**
  - テンプレートの実体化・型の制約による影響（fmt PR #4686 の `static_cast<Char>` の追加）。名前の参照が無いため波紋調査では捉えられない。
  - テンプレートの依存型（`T::foo`）・`auto` で推論した変数・戻り値の型からの推論・オーバーロードの解決・ADL・関数ポインタと `std::function`・演算子オーバーロード。受け手のクラスを決められず `name-only`（`auto`・戻り値・名前空間の修飾・名前空間の区別は ADR-0028 で一部を扱う）。
  - 名前空間の区別（別の名前空間の同名クラスは同じクラス名として扱い `name-only`）。名前空間で修飾した呼び出し（`fmt_lib::format`）も `name-only` のまま（`auto`・戻り値・名前空間の修飾・名前空間の区別は ADR-0028 で一部を扱う）。
  - リポジトリの外（システムヘッダ・ビルドの `-D`）で定義されたマクロは置き換えられない。定義の1つでも条件に当たらないマクロは置き換えない（保守的）。
  - 空にした組は、同じ条件コンパイルの枝に複数の組があり、その中に片方だけに空の定義がある組がある場合に、誤って組にしうる（計測した3母体には無い）。
  - 規則判定（`rule`）は `[CLASS:…]` を作らず、`[CLASS:…]` のエントリのヒットは `name-only` になる。
- **再検討の条件:** 実開発のサブ機能の粒度の正解を作って評価し、`name-only` の雑音が判断の妨げになる場合は、名前空間の修飾・`auto` の型の推論等を追加の規則として検討する
  （プラン §8 に、2つの規則の後に残る name-only の内訳を記録した）。
