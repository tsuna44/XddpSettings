# ADR-0038: project-rulebook の書く場所・書式・節の決め方を1つにし、DOCS との同期をスクリプトが判定する理由

Status: Accepted
Date: 2026-11-15

経緯: PLAN-20261115-project-rulebook-contracts（約束の監査 [docs/xddp-contract-audit-2026-11.md](../xddp-contract-audit-2026-11.md) の P5）。

## Context

project-rulebook は3種のファイル（共通 `project-rulebook.md`・repo 別 `project-rulebook-{repo}.md`・cross `project-rulebook-cross.md`）からなり、
4つの書く側（init・`/xddp-fill-rulebook`・工程2 Step B3・close Step C3.5）と、close の `{DOCS}` への写しが関わる。監査で次の食い違いが見つかった。

- 節を番号で当てていた。番号の意味がファイルの種類ごとに違う（共通の 5 は禁止事項、repo 別の 5 は ADR）ので、fill-rulebook が別の節を置き換えた（A5-4〜A5-10）。
- 書く場所が「既存のコードブロックの末尾」で、どのブロックかが決まらず、例のコードブロックに書き込まれた（A5-19）。禁止事項の行の書式が書く側どうしで違った（A5-20）。
- テンプレートからの作成が3か所にあり、init は本文の `{CR}`・`YYYY-MM-DD` まで置き換え、§7 の初期行に今の CR を入れたので、最初の CR の B3 が飛ばされた（A5-3・A5-21・A5-22）。
- シングル構成で repo 別ファイルを作るかが、書く側（C3.5 は作る）と読む側（init は戻さない・fill は拒む）で違った（A5-2）。
- close は C3.5 の書き込みの前に `{DOCS}` に写し（A5-1）、写しは丸ごとの上書きで、別の作業場所の更新を消しうった（A5-28）。

## Decision

1. **節はファイルの種類と見出しの名前で決める。** 3種のファイルの節の一覧（番号・見出し・記入箇所・fill が起こすか）は `rulebook_files.py` の `SECTIONS` だけに置き、
   テンプレートの見出しとの一致をテストで確かめる。B3・C3.5 の宛先の表も見出しの名前で書き、`tools/harness/tests/test_rulebook_contracts.py` がテンプレートと照らす。
2. **書く場所は、各サブセクションの末尾の「記述欄」（`（…をここに記述する）` の行）に決める。** 例のコードブロック・デフォルト原則は書き換えない。
   記述欄がその行のままなら置き換え、記入済みなら末尾に足す。書式は、規約・パターンは `- `、禁止事項は `- ❌`・`- ⚠️`、ADR は `### ADR-NNN:`、どれも末尾に `（出典: …）`。
3. **未記入は記入箇所の状態で判定する。** 節のすべての記入箇所が未記入なら `unfilled`、一部なら `partial`。fill-rulebook は節番号の指定が無ければ `unfilled` の節だけをドラフトする。
   当てはまらない記入箇所は「該当なし」と書けば記入済みになる。これで、当てはまらないサブセクションが1つ残るだけで、人が書いた節をドラフトし直し続けることがない。
4. **repo 別ファイルは構成によらず作る。cross はマルチ構成だけ。** 後から repo が増えても、repo 固有の知見の置き場所が変わらないようにするため。
   共通ファイルにはプロジェクト全体（すべての repo）に当てはまるものだけを書く。シングル構成では「すべての repo に共通」を確かめられないので、
   fill-rulebook は共通の 2.・3.・4.・6. をコード調査から起こさず、repo 別に起こす（構成による判定もスクリプトが返す）。
5. **ファイルの作成と `{DOCS}` との同期はスクリプトが行う。** `ensure` はテンプレートから作るとき `{REPO_NAME}` と §7 の初期行（`{INIT_DATE}`・`{INIT_CR}`）だけを置き換える。
   `{XDDP_DIR}/.rulebook-sync.json` に「最後にそろえたときの内容のハッシュ」を持ち、片方だけが変わっていればもう片方に写し、両方が変わっていれば書かずに競合として
   close の Step D で差分を示して人が選ぶ（`resolve`）。init は競合でも止めず、示すだけにする。
6. **close は C3.5・C3.6 を `promote.py run` の前に行う。** knowledge agent が失敗したとき（エラー・出力が無い・今回の出力でない・末尾の `## 完了` が無い）は、
   rulebook を写さず（`run --skip-rulebooks`）、`FAILED_TARGETS` に入れて完了の表示を「⚠️」にする。

## Consequences

- 3方向のマージはしない。rulebook は節の中の行を人も書くので、行の足し込みを機械で決めない。両方が変わったら人が合わせる（受け入れる限界）。
- 基準のハッシュが無い既存の作業場所では、`{XDDP_DIR}` と `{DOCS}` の内容が違う rulebook は最初の判定で競合になる。
- 既存の rulebook のうち、例のコードブロックに書かれてきた内容は書き直さない。記述欄のプレースホルダーが残っている節は未記入と判定されうるが、
  fill-rulebook は人が確かめてから記述欄だけに書くので、既存の内容は消えない。
- テンプレートの例と見出しの Web への偏り（「DB・API」「API バージョニング規約」等）は直していない。見出しを変えると宛先の表と読む側の参照がすべて変わるので、別に扱う。
