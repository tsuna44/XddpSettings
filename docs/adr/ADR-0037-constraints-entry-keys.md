# ADR-0037: 制約のエントリをスクリプトが書き、同じエントリかを元の文書の項目を指す鍵で決める理由

Status: Accepted
Date: 2026-11-15

前提: [ADR-0033](ADR-0033-constraints-module-key.md)（置き場所 `{MODULE}` の決め方）。
経緯: PLAN-20261108-code-knowledge-writers（約束の監査 [docs/xddp-contract-audit-2026-11.md](../xddp-contract-audit-2026-11.md) の P2）。

## Context

code-knowledge の制約（`{KNOW}/{MODULE}/constraints.md` の `[CK-NNN]` エントリ）は、3つの経路が書く。xddp-close Step C3.6（SPO §5.6・LL・TRS の NG）、
xddp-survey の knowledge 昇格（SURVEY §2.6）、xddp-update-knowledge（人の入力）である。ADR-0033 で置き場所は `knowledge_place.py place` が決めるようにしたが、
採番・同じエントリかの照合・節と欄の書式は、3つの経路の LLM がそれぞれ解釈していた。監査で次の食い違いが見つかった。

- 同じエントリかを「同じ出典」で決めていた。1回の survey の昇格・1回のクローズの SPO §5.6 の行は出典がすべて同じなので、
  同じ置き場所に入る制約が互いに置き換わり、最後の1件しか残らなかった（A1-1・A1-3）。手での登録も、同じ出典の別の制約を黙って置き換えた（A1-2）。
- TRS の NG の鍵 `CR-{CR} / NG-{NNN}` に実行回が入っておらず、回ごとに `NG-001` から振る NG が置き換わった（A1-4）。
- 出典の書式が経路とテンプレートで揃わず、`CR-` で始まる CR フォルダ名では接頭辞が二重になった（A1-5）。`**対象:**` 欄が節によって無かった（A1-6）。
- 予約名（`_structures` 等）と同じ名前のディレクトリの制約は、置き場所がその予約名になり、`list_places` が除くので読まれなかった（R1）。
- 人の入力のパスの `\` を JSON にそのまま埋め込むと、黙って `no-path` になった（A1-17）。

## Decision

1. **制約のエントリは `knowledge_place.py upsert` が書く。** 置き場所の決定・`[CK-NNN]` の採番・同じエントリかの照合・節と欄の書式・`**対象:**` を
   スクリプトが決める。LLM は、どの知見を昇格するか・本文・鍵の元になる項目の位置を決めるだけにする。エージェント・スキルは `constraints.md` を
   直接 Edit・Write しない。書式の正はテンプレート（`code-knowledge-constraints-template.md`）で、スクリプトの節・欄の定数をテストでテンプレートと突き合わせる。
2. **同じエントリかは、出典ではなく、元の文書の項目を指す鍵で決める。** 鍵は見出しの次の行の `<!-- key: … -->` に書き、人の読む表示に出さない。
   SPO §5.6 は行の順番、LL は ID と節（1件の LL が2つの節に昇格しうるため）、TRS はファイル名（実行回を含む）と NG、SURVEY は §2.6 の項目の順番を指す。
   出典は人が読む表示で、照合には使わない。
3. **経路の名前空間と鍵の接頭辞はスクリプトが付ける。** `--batch-cr {CR}` は `cr:{CR}:`、`--batch-survey {SURVEY_FILE}` は `survey:{ワークスペースからの相対パス}:`、
   手での登録は `manual:{file}:{CK-NNN}`。LLM が相対パスを組み立てると書き方が揺れ、やり直しで鍵が変わって重複するため。
   固定の接頭辞で分けるので、CR フォルダ名が `manual` 等でも他の経路のエントリと混ざらない。
4. **やり直しで、前回書いたが今回書かなかったエントリは消さずに人に示す（`not_written`）。** 書かなかった理由は、人が元の項目を消した・行の番号がずれた・
   LLM の昇格の判断が変わった、のどれもありうる。最後の場合は誤りではない知見なので、スクリプトは消さない（人の判断 2026-11-08 の案C）。
   昇格する制約が0件のときも空の入力で実行し、前回のエントリをすべて示す。移動でエントリが無くなったファイルも消さずに `emptied` で示す。
5. **手での登録は、置き換えるかを人が選ぶ（`--dry-run` の `existing` と `replace`）。** 置き換えたエントリの鍵は新しい `manual:` にする。
   人が書き直した内容を、元の経路のやり直しで上書きしないため。代わりに、元の経路をやり直すと元の項目は別のエントリとしてもう一度足される。
   人が直接 `constraints.md` を書き直すときは、鍵の行も消す（消さないと、やり直しで上書きされる）。鍵の行の無いエントリは、照合・削除の対象にしない。
6. **置き場所の入力（`targets`）と表示だけの対象（`subjects`）を分ける。** 置き場所は `placed` の対象すべての共通の先頭で決まるので、手での登録の
   自由記述の「対象」に書かれたパスで、人が明示した置き場所が変わらないようにする。
7. **予約名と衝突したら、読まれる `fallback` に置く（R1）。** `reserved_collision` で人に示す。`_root`・`_general` と同じ名前のディレクトリは、その置き場所に混ざるが読まれるので変えない。
8. **書く前にすべてを検証し、誤りならどのファイルも変えない。** 制御文字（`\` の書き漏らし）・見出しや鍵の行と同じ形の本文・`fallback` の誤り・鍵の重なりは終了コード 2。
9. **宛先のパスは宛先ルーティング表だけが定義する。** refcheck 検査H が、他のファイルが宛先のパスを書いていないかを見る。
   制約の置き場所にしない予約名と `constraints.md` のファイル名は `docs_layout.py` に置き、`knowledge_place.py`・`ai_index.py`・`domain_refs.py` が import する。

**却下した案:**
- 鍵を `[CK-NNN]`＋タイトルにする: タイトルは LLM が書くので、やり直すたびに言い回しが変わって二重になる。
- 鍵を出典の文字列のまま、出典を項目ごとに細かくする: 出典が読みにくくなる。照合の値と表示を分ける。
- 3つの経路の LLM の手順に「項目ごとに別のエントリにする」と書き足すだけ: 3か所の解釈がまたずれうる。
- やり直しで今回書かなかった制約をスクリプトが消す: LLM の判断の変化のときも、誤りではない知見が消える。
- upsert をやめて毎回追記だけにする: やり直しで同じ制約が増え続ける。
- 予約名と衝突したら置き場所に接頭辞を付ける: 読む側すべてに同じ変換が要る。書かない案は知見が失われる。

## Consequences

- 既存の `constraints.md` のエントリは鍵の行を持たないので、`upsert` は照合も削除もしない（足すだけ）。予約名と同じ名前のディレクトリに今までの規則で
  書かれた制約は読まれないままなので、人が移す。移行の手順は用意しない（後方互換性ポリシー）。
- 受け入れる限界:
  - SPO §5.6・SURVEY §2.6 の鍵は行・項目の順番なので、途中の行を消すと後ろの鍵がずれ、同じ内容が別の鍵で書き直されて、古い鍵のエントリが `not_written` に出る。
  - `/` を付けてリポジトリのルートからの意味で書いた、まだ無いディレクトリのパス（`/src/newdir/x.c`）は `outside-repo` になる
    （実在しないディレクトリでは、ワークスペースの外の絶対パスと区別できない）。
  - 本文の欄で `\` を書き漏らして `\n`・`\t` になったもの（`C:\temp` 等）は検出できない（本文には改行・タブが普通に入るため）。
- 共有の知見（`_structures/`・`_constants/`・`_flows/`）のエントリは、ドメイン名・図の中身が意味判定なので、引き続き LLM が書く。
