# 約束の監査 — やり直しの追加の指示（A3・A4・A5）

前回の監査では、検証者の抜き取り確認で、書く側・読む側の漏れ（監査者の一覧に無い書く側・読む側）が見つかった。漏れていた箇所に食い違いは無かったが、人の判断により、この領域の監査をやり直す。
`common.md` の指示に、次を足して従う。

## 前回の結果の扱い
- 前回の監査者の報告（依頼文の `audit-reports/{領域}.md`）と、その検証者の報告（`audit-reports/V*.md`。依頼文で指定）を Read してよい。ただし**前回の一覧を前提にせず**、約束の列挙と書く側・読む側の洗い出しをやり直す。
- 出力は、**前回の報告を置き換える完全な報告**にする（前回から変わらない約束・指摘も省略せずに書く）。
- 指摘の番号: 前回と同じ食い違いは**前回の番号**を使う。新しい食い違いは前回の最大の番号の続き（例: A3-24 から）。前回の指摘で、今回は食い違いではないと判断したものは「前回の指摘のうち取り下げるもの」に理由と根拠を書く（黙って消さない）。

## 書く側・読む側の洗い出し（前回の漏れへの対策）
約束ごとに、書く側・読む側を**2つ以上の独立した探し方**で探す。少なくとも次の種類から2つ以上を使う:
1. ファイルのパス・ファイル名の一部（例: `rulebook-cross`・`module-catalog`）
2. 節・見出し・表の列の名前（例: `## 知見詳細`・`タグ別インデックス`）
3. 変数名・入力のキー・スクリプトの関数名（例: `CATALOG_FILE`・`LESSONS_FILE`・`append_breaking_warning`）
4. プレースホルダー・書式の文字列（例: `### LL-`・`{CR}`）
5. 参照のたどり（書く側・読む側のファイルの中の参照から）

範囲は `CC/skills`・`CC/agents` の全体（`tests/` を含めて検索し、テストは「読む側」ではなく参考として扱う）。説明の文・開発用のひな形（`xddp-templates/`）に出てくるものも、一覧に「説明のみ」と区別して載せる。
「確認した約束の一覧」の「見つけた方法」の列には、使った探し方をすべて書く（例: `(1) grep -rn 'rulebook-cross' CC/skills CC/agents ／ (3) grep -rn 'CROSS_RULEBOOK' …`）。

## 出力に足すもの
- 「前回からの変更」の節: 新しく足した約束（一覧の #）・新しく見つけた書く側・読む側（約束の # とファイル:行）・新しい指摘・取り下げた指摘・番号を変えずに内容を直した指摘。
