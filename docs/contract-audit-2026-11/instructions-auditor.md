## 「約束」の範囲
2つ以上のファイル（スキル・エージェント・テンプレート・スクリプト）が、同じものを書く側・読む側として扱っているもの:
- ファイルのパス・名前の形
- 見出し・節の名前と番号
- 表の列・行のラベル
- メタ行・エントリの書式
- JSON・stdout のキーと値の語彙
- エージェントへの入力（`Inputs` の名前・中身。パスかファイルか・存在しない場合の意味）
- テンプレートのプレースホルダー（テンプレートに書く側と、埋める側）
- 書く時期と読む時期（読む側が読む時点で、書く側は書き終えているか）

対象外（`tools/harness/refcheck.py` が既に機械検査している）: 検査A（`apply "## 見出し"` の存在）、検査B（`subagent_type` のエージェントへの解決と Inputs のキー名）、検査D（スクリプトのサブコマンド・フラグ）、検査E・F・G。
ただし、検査B は Inputs のキー名しか見ないので Inputs の中身（パスかファイルか・存在しない場合の意味）は対象。検査C（テンプレートのプレースホルダー）は警告だけなので、プレースホルダーの約束も対象。

- 書く側が工程の成果物（CR の成果物・そのテンプレートとエージェント）で、読む側が知識ハブのスクリプト・スキルである約束は、読む側が書き出すもの（知識ハブのファイル）が属する領域が担当する。例: 各成果物の「気づき・提案メモ」の節を `collect_insights.py` が読んで INSIGHTS を書く約束は A3。close の knowledge agent が SPO §5.6・TRS の NG を読んで constraints.md を書く約束は A1。`xddp-11-specs` の agents が SPO・CHD を読んで latest-specs を書く約束は A4。

- 担当外の約束で食い違いに気付いたら「担当外（A?）」と印を付けて報告する。

## 手順
1. 領域の約束を列挙する。最初に読むファイルは依頼文の一覧（検索語で得たもの）とし、そこから参照をたどって書く側・読む側を足す。
   - **粒度（直した点 b）:** 「確認した約束の一覧」の1行は、食い違いの有無を**別々に判断できる単位**にする（例: 表の列の並び・キーの列・リンクのパスの形・行の範囲は、別々の行にする）。複数の約束を1行にまとめない。
   - **見つけ方（直した点 c）:** 書く側・読む側のファイルごとに、それを見つけた方法を書く。検索で見つけたなら「パターンと範囲」（例: `grep -rn 'constraints.md' CC/skills CC/agents`）、参照をたどって見つけたなら「参照元のファイル:行」。
2. 約束ごとに、すべての書く側とすべての読む側を読み、食い違いを探す（形式・語彙・パスかファイルか・存在しない場合の扱い・時期）。ファイルの一部の範囲だけを読んだ場合は、その範囲を「読んだファイルの一覧」に書く。
3. 時期の約束は、1つのファイルでは判断できないので、「書く側のスキル・ステップ見出し → 読む側のスキル・ステップ見出し」の順序を表にし、その順で実行される根拠（ファイル:行。例: `xddp-11-specs` の後に `xddp-close` を実行する、close の Step の順）を添える。
4. 食い違いを見つけたら、書く側と読む側の該当箇所（ファイルパス・節名・行番号）と、食い違いの内容・起きること・確度を書く。
   - **粒度（直した点 b）:** 別々に直せる食い違いは別の指摘にする（ひな形の不整合が6つあれば6つの指摘。1つの指摘に「・」で並べない）。
5. 修正はしない。

確度の凡例:
- ✅ 確かめた: 両側のコードを読んで食い違いを確認した（監査者はスクリプトを実行しないので、✅ は「両側を読んで確認した」の意味）。
- 🔶 推論: LLM の振る舞いに依存する等、コードからは確定できない。推論である旨と根拠を書く。
- ⬜ 未確認: この監査では確かめていない。

重大度の案（付けてよい。確定は統合で行う）: 🔴 知見・成果物が黙って失われる／誤った内容が下流に渡る、🟡 人が気付ける形で失われる・限定的な条件でだけ起きる、🔵 記述の不整合（動作への影響は無い）。

ADR（`{W}/docs/adr/`）に受け入れた制限として書かれているものは、その旨（ADR のファイル:行）を添える。

## 出力の書式（最終メッセージとして Markdown で返す。ファイルには書かない）
指摘の番号は `{領域}-{n}`（例: `A1-1`）とする。
1. **確認した約束の一覧**（食い違いが無かったものも全部）: 表の列は `# | 約束 | 書く側（ファイル:行・節） | 読む側（ファイル:行・節） | 見つけた方法（書く側・読む側ごとに、パターンと範囲、または参照元のファイル:行） | 結果（食い違いあり {領域}-n／なし）`
2. **時期の約束の表**: `書く側（スキル・Step） | 読む側（スキル・Step） | 順序の根拠（ファイル:行） | 結果`
3. **指摘**（担当の食い違い）: 指摘ごとに、約束／書く側（ファイル:行・節）／読む側（ファイル:行・節）／食い違い／起きること（どの工程で何が失われるか・誤った内容が下流に渡るか）／確度（✅／🔶／⬜ と根拠）／重大度の案／修正案（決めない。任意）。
4. **担当外の指摘**（あれば。印「担当外（A?）」）: 指摘と同じ項目。
5. **段階2b の候補**（あれば。印「段階2b」）: 書く側・読む側（ファイル:行・節）・内容・確度。無ければ「なし」。
6. **読んだファイルの一覧**（全文か、読んだ範囲か）と、**確認していないこと**（「確認していません」と明示）。
